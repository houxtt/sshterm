# sshterm 补全计划与工具链替换评估

> 基于源码审查 · 2026-08-16 · 仓库: `C:\tools\sshterm`
> 前置文档: `docs/sshterm-architecture.html`

## 一、补全计划：分屏 / SSH 隧道 / EXE 打包

原则：优先可落地产出，减少单点大改；保持 Node + 浏览器架构不变。

### 1. EXE 打包（P0，1 天内可验证）

现状：`scripts/build-exe.js` 已写好，调用 `caxa` 将 Node + 项目打包为 `dist/sshterm.exe`。
风险点：`caxa` 打包体积偏大、chrome-headless-shell 等 vendor 资源可能不必要进入最终包。

**可执行步骤**：
1. 在开发机执行 `node scripts/build-exe.js`，确认生成 `dist/sshterm.exe`。
2. 验证双击启动：自动起 Node 服务 + 打开浏览器 `127.0.0.1:8787`。
3. 若体积过大，调整 caxa 参数，排除 `tests/`、`perf-proto/`、`vendor/chrome-headless-shell`（运行时非必需）。
4. 替换 `launcher.vbs` 路径为 `dist\sshterm.exe --auto-exit`，实现静默启动 + 关闭浏览器后服务自退。

产出：可直接分发的独立 EXE。

---

### 2. 分屏（P1，前端为主，2-3 天）

现状：`web/app.js:1219-1266` 已有“第二 pane”雏形——只支持一个 `extraPane`，左右并排，无拖拽调整比例、无上下分屏、无多标签栏复用。

**问题**：
- 只允许 1 个 pane，不支持 2x2 或 1+N
- pane 尺寸固定 CSS，不支持拖拽分割条
- `pane1` 类名硬编码，关闭逻辑仅删除首个 pane
- 没有 pane 级别的 tab 状态指示 / 关闭按钮布局

**可执行步骤**：
1. 将 `extraPanes` 从 `Array` 改成更结构化的对象，并抽象 `PaneManager`（新建/关闭/激活/布局）。
2. 增加分割容器 `.split-container`，支持横向/纵向 flex + 可拖拽 divider（实现 30-70% 比例记忆）。
3. 支持最多 4 个 pane（2x2），点击“分屏”在当前 pane 内创建子 pane，已有 pane 不做限制。
4. 服务端无需改动：现有 `connect/disconnect/resize` 基于 connId 路由，每个 pane 已有独立 connId。
5. 增加测试 `tests/ui_split_quad.js` 覆盖 4-pane 输入回显。

产出：可用分屏功能，保留当前架构。

---

### 3. SSH 隧道 / 端口转发（P1，服务端 + 前端，3-5 天）

现状：`ssh2` 原生支持 `direct-tcpip`（本地转发）和 `forwardOut`（远端/动态转发），但 sshterm 未做任何 UI 或管理逻辑。

**可执行步骤**：
1. 服务端新增 `tunnel` WS 消息类型：
   - `tunnel-list` → 返回当前会话的隧道列表
   - `tunnel-add` → 参数 `{type:'local'|'remote'|'dynamic', localPort, remoteHost, remotePort}`
   - `tunnel-remove` → 按 id 删除
2. 在 `SSHConnection` 中增加 `this.tunnels = new Map()`，用 `client.createConnection` / `client.forwardOut` 实现。
3. 前端新增“隧道管理”抽屉：已建隧道列表 + 新建表单 + 删除按钮；实时显示本地监听端口。
4. 限制：单会话最多 8 条隧道；端口冲突提示。

产出：可用的 SSH 隧道管理面板，满足内网穿透 / 代理跳板场景。

## 二、工具链替换评估：sshterm 能否替换当前某部分

基于你的使用场景（嵌入式 Linux/BSP + 智驾域控 + 串口调试 + 内网设备发现），典型现有工具链：

| 场景 | 常见现有工具 | sshterm 覆盖 | 结论 |
|---|---|---|---|
| SSH 登录板卡（GK1221/TDA4VM/RK3588） | PuTTY / KiTTY / Tabby | ✅ 密码/密钥/代理/自动重连/会话管理 | **可直接替换** |
| Telnet 设备/路由器 | PuTTY | ✅ IAC 协商 + 自动登录 | **可直接替换** |
| 串口调试（WCH/车载模组） | SecureCRT / MobaXterm / 串口助手 | ✅ 全参数 + HEX + DTR/RTS/Break + 占用检测 | **基本可替换**；缺：串口时间戳/日志自动保存、条件触发 |
| SFTP 文件传输 | WinSCP / Xftp / MobaXterm SFTP | ✅ 浏览/下载/上传/断点续传/目录打包 | **可直接替换** |
| 端口扫描/设备发现 | nmap / Advanced IP Scanner | ✅ 内置 CIDR/范围扫描 | **可替换轻量扫描**；缺：服务指纹识别、UDP |
| ZMODEM 传输 | lrzsz 终端 / SecureCRT | ⚠️ 仅接收端最小实现，**发送 sz 未实现** | 暂不能完全替换 |
| 分屏/多窗口 | MobaXterm / WindTerm / Tabby | ⚠️ 已有双 pane 雏形，未完善 | 短期依赖 WindTerm/Tabby |
| 独立 EXE 分发 | 安装版软件 | ⚠️ caxa 脚本已有，待验证 | 有望 1 周内实现 |
| 脚本/宏自动化 | SecureCRT VBS / Xshell 脚本 | ⚠️ 快捷命令集已有，缺复杂流程编排 | 基本脚本可替换，复杂流程需扩展 |

### 推荐替换路径（最小迁移成本）

1. **本周**：用 sshterm 替代 PuTTY/KiTTY 做日常 SSH + 串口调试。保留 1 个备用终端工具（如 KiTTY）处理 sshterm 暂时不支持的超长输出过滤 / sz 发送。
2. **1 个月内**：EXE 打包完成 + 分屏可用后，sshterm 成为主力；WinSCP 可退出。
3. **保留不替换**：
   - nmap（深度扫描 / 漏洞探测）
   - lrzsz（sz 发送文件）
   - 复杂串口分析工具（Saleae/Serial Analyzer），sshterm 定位是“调试接入”，不是“协议分析”
